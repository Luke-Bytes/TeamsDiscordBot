# Friendly Wars scenarios - organiser guide

Current gameplay, separate from the historical design proposals. Only one scenario can be selected per game.

## Announce and prepare a scenario game
As an organiser, use `/announce start scenario:` and choose one of the seven scenarios alongside the normal announcement options, then confirm the announcement as usual. The scenario explanation is attached to announcements and the game feed. Players register normally. On registration, Mystery Dungeon and Partners in Crime open optional private interactions. The bot schedules team generation for 15 minutes before the game; review and confirm the proposed teams, then appoint captains within them. The People's Captains opens voting 35 minutes before the game and closes 20 minutes before, if prerequisites are met; confirm the election result, then normal snake drafting is available. No self-nomination is needed. Masked Draft, Draft Roulette and Captain's Wildcards use ordinary captain selection before their draft starts. Cursed Classes opens when teams, both captains and a valid approved pool are ready. Automatic stages can pause if prerequisites are missing or roster changes make the result unsafe. Let scheduled work run instead of manually advancing every stage. Review and confirm results using the organiser controls in the game feed, team-picking channel or scenario dashboard.

## Scenario status, reminders and resend prompts
Use `/game scenario status` in the game server as an organiser. It shows the selected scenario, preparation progress, scheduled stages, deadlines, response and delivery progress, blockers and eligible controls. It is not a viewer for other people's private choices. Refresh the dashboard for the latest information. If someone misses a DM, ask them to click Open My Scenario or use `/game scenario open`. To resend a prompt use `/game scenario open user:@player` (organiser only); this sends it privately to the target, it does not let you answer as them. If their DMs fail, use the self-open route. Only eligible, unexpired interactions can be reopened. The bot attempts one reminder for incomplete questionnaire, preference, ballot or class-assignment interactions when time permits. Confirm results only after checking the roster and any reported issues.

## Scenario game start, team selection and Cursed Classes pool
Normal captain and team commands still apply when the selected scenario permits them. A scenario that owns captain selection, team formation or the draft blocks competing workflows until it is complete. For Cursed Classes, approve 3-20 distinct valid classes before the draw via `/game scenario pool classes:Civilian,Farmer,Builder` (example only, check actual eligibility). Both teams must have at least three players and captains; exclude conflicts with class bans and applicable restrictions. The bot opens assignments automatically once prerequisites are ready. Both captains must submit before the deadline. Affected players can use `/game scenario report-class` to report unavailable class access before start. Resolve reports and missing assignments rather than ignoring them. The Discord bot cannot enforce classes inside Minecraft. Before `/game start`, check status, confirm required scenario results and normal team/captain prerequisites. Do not bypass a scenario start blocker. Once preparation finishes, ordinary match start, gameplay, result recording and cleanup continue. Rating follows the existing season and match policy; selecting a scenario alone does not change it.

## Scenario recovery, manual start, resume and cancel
If a scenario hasn't started, check `/game scenario status` and the game feed first: a stage may be waiting for a scheduled time, sufficient players, captains, class pool, confirmation or roster review. Use the dashboard's eligible stage button or `/game scenario start` (optional stage argument) only if necessary; it cannot bypass prerequisites. After a restart, unfinished recovered scenario interactions may be paused for review; don't assume timers, old prompts or a draft automatically replay. Inspect the dashboard and reconcile the roster and progress first. If safe, `/game scenario resume` resumes organiser-controlled preparation, then inspect status and manually start an eligible stage. Interrupted drafts must be cancelled and rebuilt.

For an election with a result, review the roster or use the dashboard to replace an unavailable captain with the next eligible candidate who received votes; do not rerun voting. If recovery is unsafe or the election fails (too few votes, too few supported candidates or roster change), cancel the scenario and return to ordinary captain selection. To abandon only the scenario before match start, use `/game scenario cancel` as an organiser; cancel any active team-picking session or preview first. Existing finalized teams remain unchanged; verify teams, captains and roles before proceeding normally. This does not cancel the whole announcement. Do not reset or retry blindly if ordinary game recovery is blocked.

## Scenario privacy and live questions
Scenario rules describe general behaviour, not current game facts. Navi has no dedicated authorised live scenario snapshot tool; don't infer which scenario is selected, which players responded or what a private choice was. Check the announcement and game feed for the selected scenario and published results; organisers can inspect the private status dashboard for progress. Never disclose or infer individual quiz answers, hidden personality types, private partner preferences, individual election votes, unrevealed masked draft identities, unsubmitted wildcard choices or unrevealed class assignments. The excluded developer command debug-scenario is not a gameplay command and should never be recommended to players. No scenario combinations or extra proposed powers are supported.
